# Game library backend rules

## 术语

所有者是首次创建游戏 ID 的账号；墓碑保留该归属。公开内容允许匿名读取，私有内容仅所有者可读。账号注销是不可恢复终态。

## 硬限制（不可违反）

- 使用 Go + GORM + MySQL。注册一律进入 pending，必须经管理员审核才能签发 API Token；管理员命令不暴露 HTTP 管理入口。
- 密码只存带随机盐和迭代参数的 PBKDF2-HMAC-SHA256 派生值，恒定时间比较。未知用户名与错误密码保持相同响应和相当校验成本；登录/注册限流。
- 凭据使用密码学随机数，只存摘要，限期且可撤销。任何日志、URL、响应错误都不得含密码、Token 或数据库 DSN。
- 登录会话 `ls_`、API Token `gs_`、游玩凭据 `ps_` 权限不互串。账号会话管理自己的 Token 与注销；游玩会话仅限绑定玩家/游戏。客户端自报成绩不是可信结算依据。
- 注销必须同时核对本账号登录会话、密码及账号名。同一事务内销毁全部凭据、随机替换密码派生值、标记 deleted；保留账号名和游戏归属，不删除其游戏与成绩。
- 游戏默认私有，只有所有者可写。公开端点允许无凭据或不可用凭据按匿名读取公开内容；需要身份的端点仍拒绝缺失/无效 Token。私有元数据/包不得被公开缓存或绕过鉴权静态暴露。
- 上传最大 512 MiB。`.game` 与裸 `.pck` 均必须校验；容器防穿越、符号链接、加密、可执行扩展和解压炸弹；pck 独立校验头、路径、版本及内容类型。未知结构 fail-closed。
- 使用服务端生成路径、流式限量上传、临时文件及原子发布；服务端计算大小/SHA256，不信任上传方声明。
- 游戏 ID 全局稳定且保留墓碑，删除后其他账号不可接管。替换/删除不会立即回收旧不可变包，防止破坏在途下载。
- 保留 `gamesource/1`、HEAD、Range 和校验信息。生产使用 HTTPS，不关闭证书验证。
- 成绩按游戏/玩家/模式/榜保存最佳值，提交 ID 按游戏/玩家幂等；同 ID 不同内容必须冲突，不可串榜。

## 软限制（可权衡）

每实例最多 4 个并发上传，暂不提供队列。离线数据回收由操作员在备份与保留窗口后安排。

## 权限规则

| 角色 | 行为 | 限制 |
| --- | --- | --- |
| 操作员 | 审核账号、签发/撤销 Token | 服务端本机命令 |
| 待审核玩家 | 登录查看状态 | 不授予 API 操作权限 |
| 已审核玩家 | 管理自己的 Token 和账号 | 不可修改他人内容 |
| 所有者 | 上传和管理自己的游戏 | 包校验与可见性规则始终生效 |
| 匿名用户 | 读取公开游戏/公开榜单 | 不披露私有记录 |

## 边界条件

公开转私有只阻止后续读取，不能召回已下载内容。历史账号迁移保留有效状态；无密码账号不能登录但既有 API Token 仍有效。账号注销不可恢复，重新注册不可抢占同名。更新或回滚数据库前必须保留备份。

## 审计与追踪

保留账号创建/审核/注销时间、游戏更新时间和所有者。注销销毁凭据行，不假称它们仍有完整审计记录；操作员独立保存审核记录。不得记录凭据明文。本期不提供完整事件审计平台。
